## 完成内容

### 1. Match 数据模型（任务 #226）
- 新建 `matches` 表，包含状态机 CHECK 约束
- 状态：CREATED → REGISTERING → READY → LIVE → FINISHED → ARCHIVED
- 新建 `match_participants` 表（支持红蓝双方/自由报名）

### 2. Match 状态机逻辑（任务 #230）
- 实现 `MATCH_STATUS` 枚举
- 实现 `isValidTransition()` 状态转换验证
- 实现 `transitionMatchStatus()` 状态转换执行（带乐观锁）
- 添加 `matchStatusMiddleware` 中间件

### 3. routes/matches.js 路由（任务 #227）
基础 CRUD 路由：
- `GET /api/matches` - 列表查询（支持 status 过滤）
- `GET /api/matches/:id` - 详情（含参与者）
- `POST /api/matches` - 创建比赛
- `PATCH /api/matches/:id/status` - 状态转换
- `POST /api/matches/:id/participants` - 报名
- `PATCH /api/matches/:id/score` - 更新比分/MVP

### 4. Socket.IO 轻量同步（任务 #228）
添加 3 个 Socket 事件：
- `match:create` → 广播 `matchCreated`
- `match:update` → 广播 `matchUpdated`（状态变化自动触发 `matchStarted`/`matchFinished`）
- `match:score` → 广播 `scoreUpdated`

### 5. 数据库迁移脚本（任务 #229）
- 创建 `migrate-competitions-to-matches.js`
- 兼容策略：新比赛走新模型，老比赛保留
- 可选择性执行迁移（不强制）

## 技术要点

1. **向后兼容**：不删除 `competitions` 表，新旧系统并存
2. **状态机约束**：数据库层（CHECK）+ 应用层双重验证
3. **乐观锁**：状态更新使用 `WHERE id = $1 AND status = $2` 防止并发问题
4. **轻量设计**：Socket 只同步核心数据（状态/比分/MVP），不做复杂实时系统
